# 03. 플랫폼 제약 및 설계 대안

“홈 화면 배경에서 물고기가 돌아다니고, 터치하면 반응한다”는 컨셉을 **Android / iOS 현실**에 맞게 조정하기 위한 문서입니다.

---

## 1. 요약 표

| 기능 | Android | iOS |
|------|---------|-----|
| **라이브 배경화면** | ✅ WallpaperService | ❌ 서드파티 앱 라이브 배경 불가 |
| **홈 화면 임의 위치 터치 → 게임 반응** | ✅ (배경 설정 시) | ❌ (홈은 SpringBoard 제어) |
| **앱 아이콘 옆·위 홈 영역** | △ 위젯 영역만 | △ WidgetKit 영역만 |
| **잠금 화면 연동** | △ 제조사·OS별 | △ 위젯·Live Activity 수준 |
| **배터리 백그라운드 연산** | △ 제한적, FPS 조절 필수 | △ 위젯 타임라인 갱신 제한 |

**결론**: **Android = 풀 비전**, **iOS = 위젯 + 앱 내 미러 + (선택) Live Activity** 로 **체감 동등화**를 노린다.

---

## 2. Android

### 2.1 가능한 것

- **Live Wallpaper**: `WallpaperService.Engine`에서 Surface 렌더  
- **터치**: `onTouchEvent` → 파문·scatter 구현 가능  
- **홈 위젯**: `AppWidgetProvider`로 수족관 일부 + 탭 인텐트  
- **앱 아이콘과의 관계**: 라이브 배경은 **아이콘 뒤 레이어**; 아이콘 자체를 “수족관 안”에 넣는 것은 **런처 커스텀**이 아니면 불가 → **위젯으로 ‘수족관 블록’ 배치**가 현실적  

### 2.2 주의

| 이슈 | 대응 |
|------|------|
| 배터리 | 화면 OFF 시 `onVisibilityChanged(false)` → 애니 정지 |
| 메모리 kill | 상태는 Supabase+로컬 캐시, 재시작 시 복원 |
| 제조사 절전 | WorkManager + 사용자 “배터리 예외” 안내 |
| Play 정책 | 배경 권한·데이터 수집 고지 |

### 2.3 “앱 아이콘 화면에 수족관 배치” 해석

사용자 의도는 다음 중 하나일 수 있음:

1. **라이브 배경**으로 아이콘 뒤 전체가 수족관 → **Android 표준**  
2. **홈에 큰 위젯**으로 수족관 블록 → **아이콘과 나란히 배치**, 터치는 위젯 내부  
3. **런처 테마** 수준 통합 → MVP 범위 밖  

**권장 MVP**: (1) + (2) 병행 — 배경은 몰입, 위젯은 퀵 먹이·터치 반응.

## 3. iOS

### 3.1 불가에 가까운 것

- 서드파티 **인터랙티브 라이브 홈 배경**(Android Wallpaper 동등)  
- 홈 화면 **빈 공간 탭**을 앱이 가로채 **물고기 반응**  

### 3.2 가능한 대안

| 대안 | 설명 | 터치 반응 |
|------|------|-----------|
| **중/대형 위젯** | 수족관 스냅샷 또는 저주기 애니 | iOS 17+ **interactive widget** 제한적 |
| **App Intent** | “먹이 주기” 버튼 | 버튼 단위 |
| **앱 내 Mirror Aquarium** | 앱 실행 시 전체화면 수족관 + 터치 | **풀 인터랙션** |
| **Live Activity** | 잠금/다이나믹 아일랜드에 상태 | 탭 → 앱 딥링크 |
| **정적 배경** | 사용자가 스크린샷 저장 | 반응 없음, 비권장 |

### 3.3 iOS UX 카피(사용자 기대 관리)

- 마케팅: “**항상 보이는 수족관 위젯** + **앱에서 만지는 수족관**”  
- Android와 동일 카피는 **리젝/불만** 위험 → 스토어 설명 분리  

---

## 4. 터치 반응 구현 매트릭스

| Surface | Android | iOS |
|---------|---------|-----|
| Live Wallpaper | Ripple + fish AI | — |
| Home Widget | Local tap → RemoteViews update / Activity | Button / App Intent |
| App Mirror View | 동일 엔진 공유 | SpriteKit / Canvas |
| Web Fishing | Pixi pointer | 동일 |

**엔진 공유 전략**: 반응 로직(`scatter`, `ripple`)을 **TypeScript(JSON 규칙)** 또는 **Kotlin/Swift 공통 스펙**으로 문서화 후 양쪽 포팅.

---

## 5. 하이브리드 연동

```
Web (꾸미기 저장)
    → Supabase aquariums.version++
    → Native: SyncWorker or push(deep link)
    → Wallpaper/Widget: snapshot + sprite manifest reload
```

**iOS 위젯**은 전체 실시간 애니보다 **스냅샷 + 하루 N회 갱신**이 안정적.

---

## 6. 스토어·권한

| 권한 | Android | iOS |
|------|---------|-----|
| 배경 설정 | `SET_WALLPAPER` | 해당 없음 |
| 네트워크 | INTERNET | App Transport Security |
| 알림(선택) | POST_NOTIFICATIONS | User permission |

---

## 7. 제품 의사결정 권고

1. **1차 출시**: Android 풀 기능 MVP  
2. **iOS 동시 출시**: 위젯 + Mirror + Web 동일 계정  
3. **“아이콘 화면 터치 반응”**: Android는 배경+위젯, iOS는 위젯·앱으로 **기능명 분리**  
4. **절전 모드**: 기본 ON, 설정에서 “생동감 모드”  

---

## 8. 참고 키워드(구현 조사용)

- Android: `WallpaperService`, `SurfaceHolder`, `RenderEffect` ripple  
- iOS: `WidgetKit`, `AppIntent`, `ActivityKit`, `WKWebView` message handlers  
- Web: `postMessage`, Supabase Realtime `aquariums` subscribe
