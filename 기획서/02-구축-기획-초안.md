# 02. 구축 기획 초안

컨셉(`01`)을 기준으로 **네이티브 · 웹앱 · 백엔드 · 인프라 · 에셋 · 프로토타입** 별 구축 초안입니다.  
엔진은 “단일 게임 엔진”보다 **역할 분리(네이티브 렌더 + 웹 UI)** 를 전제로 합니다.

---

## 1. 아키텍처 총괄

```
┌────────────────────────────────────────────────────────────────┐
│ Layer A: Native (Android / iOS)                                 │
│  · WallpaperService / Widget Extension                          │
│  · 2D 렌더 (Canvas / OpenGL ES / Metal 저해상)                  │
│  · 터치·센서 브리지, 로컬 캐시, 딥링크                           │
│  · WebView 컨테이너 + JS Bridge                                 │
└────────────────────────────┬───────────────────────────────────┘
                             │ HTTPS / postMessage
┌────────────────────────────▼───────────────────────────────────┐
│ Layer B: Web App (Vercel)                                       │
│  · Next.js App Router (권장)                                    │
│  · Lobby, Shop, Decorate, Fishing (Canvas or DOM+sprite)        │
│  · Supabase JS Client                                           │
└────────────────────────────┬───────────────────────────────────┘
                             │
┌────────────────────────────▼───────────────────────────────────┐
│ Layer C: Backend (Supabase)                                     │
│  · Postgres + RLS                                               │
│  · Auth, Storage(assets), Realtime(선택)                        │
│  · Edge Functions: 영수증 검증, 일일 상점 시드(선택)            │
└────────────────────────────────────────────────────────────────┘
```

---

## 2. 기술 스택 후보 및 권장(프로토타입)

| 영역 | 후보 | 프로토타입 권장 | 이유 |
|------|------|-----------------|------|
| **Android Native** | Kotlin + WallpaperService | **Kotlin** | 라이브 배경 API 1급 지원 |
| **iOS Native** | Swift + WidgetKit | **Swift** | 배경 대신 위젯·App Intent |
| **크로스 셸** | React Native, Flutter | **React Native** (선택) | WebView·JS Bridge 성숙, 팀 웹 스택과 맞춤 |
| **웹앱** | Next.js, Vite+React | **Next.js on Vercel** | SSR/라우팅, 배포 단순 |
| **백엔드** | Supabase, Firebase | **Supabase** | Postgres, Auth, Storage 일원화 |
| **배경 렌더** | Custom 2D, LibGDX lite | **Custom Canvas/OpenGL** | 픽셀 스프라이트만이면 엔진 과함 |
| **웹 미니게임** | Phaser 3, PixiJS, CSS sprite | **PixiJS** 또는 **Canvas 2D** | 낚시만 가볍게 |
| **에셋** | Aseprite → sheet | **Aseprite + TexturePacker** | 도트 파이프라인 표준 |

**Unity / Unreal**: 풀 3D·대형 미니게임이 아니면 **비권장**(APK/IPA·배경 메모리 부담).

## 3. 구축 영역별 상세

### 3.1 Native — Android (우선순위 P0)

#### 목표

- `WallpaperService` 기반 라이브 수족관  
- 터치 시 파문·물고기 scatter  
- Supabase에서 받은 `aquarium_snapshot` 로컬 반영  

#### 모듈

| 모듈 | 책임 |
|------|------|
| `AquariumWallpaperService` | Surface 생명주기, FPS 30 cap |
| `SpriteEngine` | 시트 컷, 애니 tick, 패럴랙스 레이어 |
| `TouchController` | tap → ripple shader / particle |
| `SyncWorker` | WorkManager 15~30분, 앱 resume 시 즉시 |
| `WebAppActivity` | Fullscreen WebView, bridge |
| `BridgeModule` | `getSnapshot()`, `applySnapshot(json)`, `openRoute` |

#### 구축 단계

| 단계 | 산출물 | 기간(가안) |
|------|--------|------------|
| A1 | 정적 배경 + fish 1종 패트롤 | 1주 |
| A2 | 터치 파문 + 반응 애니 | 1주 |
| A3 | 로컬 JSON 상태 + 수동 sync API | 1주 |
| A4 | WebView + bridge 연동 | 1주 |

#### 핵심 API (Bridge 초안)

```typescript
// Web → Native
window.AquaDesk.applySnapshot(snapshot: AquariumSnapshot): void
window.AquaDesk.previewWallpaper(): void

// Native → Web
aquarium://sync-complete?version=123
```

#### 구축 단계

### 3.4 Backend — Supabase (P0)

#### 스키마 초안

```sql
-- profiles (auth.users 1:1)
profiles (id uuid PK, display_name, created_at)

-- aquariums
aquariums (
  id uuid PK,
  user_id uuid FK,
  theme_id text,
  slots jsonb,          -- [{slotId, itemId, x, y}]
  version int,
  updated_at timestamptz
)

-- fish_instances
fish_instances (
  id uuid PK,
  aquarium_id uuid FK,
  species_id text,
  growth_stage int,
  hunger float,
  last_fed_at timestamptz
)

-- inventory
inventory (
  user_id uuid,
  item_id text,
  qty int,
  PK (user_id, item_id)
)

-- catalog (시드)
items (id, type, price_coin, asset_key)
fish_species (id, rarity, base_sprite)
```

#### RLS 원칙

- 모든 테이블: `auth.uid() = user_id` (또는 aquarium 소유자 join)  
- `catalog`만 public read  

#### Edge Functions (선택)

| 함수 | 용도 |
|------|------|
| `daily-shop-roll` | 날짜+user_id 시드 상점 |
| `fishing-resolve` | 서버에서 보상 결정(치팅 방지) |

#### Storage

```
sprites/fish/{species}/{frame}.png
sprites/deco/{id}.png
snapshots/{userId}/latest.webp   -- 위젯용
```

#### 구축 단계

| 단계 | 산출물 |
|------|--------|
| B1 | 스키마 + RLS + seed catalog |
| B2 | Auth + profile trigger |
| B3 | aquarium CRUD + version bump |
| B4 | fishing RPC + inventory |
| B5 | snapshot export (이미지 생성은 웹 또는 Edge) |

## 6. 엔진·프레임워크 결정 체크리스트

다음 항목에 **예**가 많으면 **커스텀 2D + Web** 유지, **아니오**가 많으면 **Flutter/React Native** 검토.

- [ ] 배경이 앱의 핵심 차별점인가? → Native Wallpaper 필수  
- [ ] 3D·복잡 물리가 필요한가? → 현재 No  
- [ ] 낚시가 단순 2D 타이밍인가? → Pixi/Canvas 충분  
- [ ] 팀이 TypeScript에 익숙한가? → Next.js + RN WebView  
- [ ] APK 50MB 이하를 목표로 하는가? → Unity 비권장

## 7. 오픈 이슈(결정 필요)

1. **모노레포 vs 분리**: 프로토타입은 `web` 단독 + `android` 단독도 가능  
2. **게스트 플레이**: 익명 auth vs 필수 로그인  
3. **iOS 1차 출시 범위**: 위젯만 vs 앱+위젯 동시  
4. **인앱결제**: MVP 제외 여부  
5. **다국어**: ko만 vs i18n 구조 선반영
