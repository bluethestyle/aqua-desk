01. 앱 컨셉 기획

1. 프로젝트 개요

1.1 서비스명(가칭)

「Aqua Desk」 (수족관 데스크) — 명칭은 추후 확정

1.2 한 줄 정의

사용자의 스마트폰 배경(및 홈 화면 위젯 영역) 에 도트 스타일 수족관이 상시 표시되고, 하이브리드 앱을 통해 수족관을 꾸미고 물고기를 키우며 낚시·상점으로 성장시키는 라이트 라이프·캐주얼 게임.

1.3 핵심 가치

가치 설명
항상 보이는 애완 앱을 열지 않아도 홈/잠금에서 물고기가 살아 있음
가벼운 재미 터치 한 번에 물결·도망·호기심 반응
짧은 세션 꾸미기·낚시·상점은 1~3분 단위
저전력·저용량 데이브 더 다이버식 픽셀, 제한된 스프라이트·프레임

1.4 레퍼런스

  • 비주얼: 《Dave the Diver》 — 굵은 픽셀, 제한 팔레트, 짧은 애니 루프, 작은 스프라이트 시트
  • UX 참고: 라이브 배경화면 게임, 홈 위젯 수족관, 방치형 키우기(피드·성장만 경량화)

2. 사용자 관점 경험(UX)

2.1 일상 루프(배경 레이어)

[기기 켜기/홈 복귀]
    → 배경 수족관 자동 렌더
    → 물고기 패트롤·식빵/기포 등 앰비언트 모션
    → (선택) 배경/위젯 터치 → 물결 + 물고기 반응
    → (선택) 앱 아이콘 근처 터치(Android 위젯) → 국소 반응

2.2 앱 루프(하이브리드 레이어)

[앱 아이콘 탭]
    → 로비: 내 수족관 미리보기 + 상태(배고픔, 레벨)
    → 꾸미기: 바닥·식물·장식·조명 배치
    → 낚시: 미니게임으로 새 종·재료 획득
    → 상점: 코인/재화로 용품·물고기·먹이 구매
    → 저장 → 네이티브 배경 엔진에 상태 동기화

2.3 화면 구성(앱 내, 초안)

화면 역할
로비 수족관 썸네일, 재화, 퀵 액션(먹이, 청소)
꾸미기 그리드/슬롯 배치, 인벤토리에서 드래그
낚시 타이밍·당기기 등 1스테이지 미니게임
상점 일일 로테이션, 패키지, 프리미엄(후순위)
도감 획득 물고기·희귀도
설정 배경 품질(절전/표준), 알림, 계정

2.4 터치 반응(재미 요소) — 컨셉

트리거 반응(예시)
배경 탭 Ripples 0.5~1s, 물고기 scatter → 2s 후 복귀
같은 영역 연타 작은 기포 연출, 희귀 fish peek
위젯 영역 탭(Android) 위젯 내부만 국소 파문, 아이콘 가리지 않음
장시간 미접촉 느린 drift, 가끔 yawning fish

주의: iOS는 “전체 홈 화면 라이브 배경 + 임의 터치”가 제한적입니다. 상세는 03-플랫폼-제약-및-대안.md.

3. 게임 디자인

3.1 성장·경제(라이트)

요소 설계 방향
재화 코인(일반), 진주(희귀, 낚시/도전)
물고기 종별 성장 단계 3~4, 먹이·시간 기반(오프라인 캡)
수족관 슬롯 수 제한 → 확장은 레벨/상점
낚시 스태미나 일일 N회, 실패해도 재료 소량
상점 일일 6슬롯 로테이션, 꾸미기 파츠 위주

3.2 콘텐츠 파이프라인(초기)

  1. MVP 물고기 5종 + 1종 희귀
  2. 장식 10종(바닥 3, 식물 4, 오브젝트 3)
  3. 낚시 맵 1곳
  4. 이벤트 후속: 계절 스킨, 한정 fish

3.3 그래픽 스펙(데이브 더 다이버 스타일, 저부하)

항목 가이드
해상도 물고기 스프라이트 32×32 ~ 48×48, 장식 타일 16×16
팔레트 배경+UI 합산 64색 이내 권장
애니 fish swim 46프레임, 반응 23프레임
배경 패럴랙스 2~3레이어, 정적+저주기 스크롤
에셋 스프라이트 시트 + JSON 메타, WebP/PNG8
목표 배경 RAM < 30MB, CPU 피크 배경화면에서 5% 미만(Android 중급기 기준)

3.4 사운드(후순위)

  • 배경: 무음 또는 초저음량 앰비언트(기본 OFF)
  • 앱 내: 짧은 SFX만(먹이, 낚시 성공)

03. 플랫폼 제약 및 설계 대안

“홈 화면 배경에서 물고기가 돌아다니고, 터치하면 반응한다”는 컨셉을 Android / iOS 현실에 맞게 조정하기 위한 문서입니다.

1. 요약 표

기능 Android iOS
라이브 배경화면 ✅ WallpaperService ❌ 서드파티 앱 라이브 배경 불가
홈 화면 임의 위치 터치 → 게임 반응 ✅ (배경 설정 시) ❌ (홈은 SpringBoard 제어)
앱 아이콘 옆·위 홈 영역 △ 위젯 영역만 △ WidgetKit 영역만

결론: Android = 풀 비전, iOS = 위젯 + 앱 내 미러 + (선택) Live Activity 로 체감 동등화를 노린다.

2. Android

2.1 가능한 것

  • Live Wallpaper: WallpaperService.Engine에서 Surface 렌더
  • 터치: onTouchEvent → 파문·scatter 구현 가능
  • 홈 위젯: AppWidgetProvider로 수족관 일부 + 탭 인텐트
  • 앱 아이콘과의 관계: 라이브 배경은 아이콘 뒤 레이어; 아이콘 자체를 “수족관 안”에 넣는 것은 런처 커스텀이 아니면 불가 → 위젯으로 ‘수족관 블록’ 배치가 현실적

2.2 주의

이슈 대응

메모리 kill 상태는 Supabase+로컬 캐시, 재시작 시 복원
제조사 절전 WorkManager + 사용자 “배터리 예외” 안내
Play 정책 배경 권한·데이터 수집 고지

2.3 “앱 아이콘 화면에 수족관 배치” 해석

사용자 의도는 다음 중 하나일 수 있음:

  1. 라이브 배경으로 아이콘 뒤 전체가 수족관 → Android 표준
  2. 홈에 큰 위젯으로 수족관 블록 → 아이콘과 나란히 배치, 터치는 위젯 내부
  3. 런처 테마 수준 통합 → MVP 범위 밖

권장 MVP: (1) + (2) 병행 — 배경은 몰입, 위젯은 퀵 먹이·터치 반응.

1. 프로젝트 정체성 및 노선 확정

1.1 Route A (Cozy / Zen) 확정

《어비스리움》, 《네코 아츠메》 계열의 스트레스 제로(0)형 힐링·방치성을 핵심 가치로 삼는다. 다마고치식 압박/죽음 모델은 배제한다.

  • 물고기 사망 메커니즘 전면 배제: 장시간 방치해도 물고기는 절대 죽지 않는다.
  • 죽음 모델은 불안 과금(다크 패턴) 으로 흐르기 쉽고, "항상 보이는 힐링 애완"이라는 정체성과 정면 충돌하므로 채택하지 않는다.

1.2 방치 패널티 = "불만족 상태" (죽음 없는 압박)

먹이 고갈/수질 악화 시 물고기는 기면·수면·불만족 상태로 진입한다.

  • 외형: 색이 반투명해지고, 바닥·산호 뒤로 숨어 움직임 최소화.
  • 시스템: 코인(일반 재화) 생산 중단 + 성장 정지.
  • 회복: 한 번의 먹이/청소로 즉시 회복되도록 마찰을 최소화(코지 원칙). 죄책감 연출 금지.

1.3 구독(아쿠아 패스, 월 1,900원) — 가치 재정의

"사망 불안"이 아니라 **"쾌적함과 유대감의 극대화"**를 판다.

  • 오프라인 캡 6h → 24h 확장
  • 자동 관리 봇(우렁이 장식): 불만족 상태에 빠지지 않도록 버퍼 제공(편의·성장 가속). 물고기를 살리는 기능이 아님.
  • 일일 낚시 스태미나 +2, 상점 프리미엄 슬롯 +1
  • ⚠️ 인지할 트레이드오프: 구독자는 불만족 상태를 거의 보지 않으므로 데일리 케어 루프가 일부 잠식된다. 구독자의 재방문 동기는 수집·꾸미기·소셜이 담당하도록 설계.

1.4 아트 디렉션 비전

"노스탤직 레트로 코지-젠 (Nostalgic Retro Cozy-Zen)"

  • 얕은 플래시게임 느낌 배제. GBA/고사양 아케이드급 밀도 높은 클래식 도트 기조.
  • 그 위에 현대적 수중 라이팅(God Rays·굴절·발광) 을 얹어 고전 감성 + 현대적 세련의 균형.

2. 네이티브 레이어: 제약과 우회 (엔지니어링 현실성)

03 문서의 플랫폼 한계 분석을 전제로, 기획 보강안에서 네이티브 샌드박스가 실제로는 못 하는 연출을 실현 가능한 형태로 교정한다.

2.1 셸 구조: 얇은 네이티브 + WebView (RN 미채용)

  • 라이브 배경은 Kotlin WallpaperService가 별도 컴포넌트로 구동되므로, RN으로 만들 수 없다.
  • 앱 UI는 전부 Vercel 웹앱(WebView). 따라서 RN 런타임을 떠안을 이유가 없다.
  • → 얇은 네이티브 셸(Kotlin Activity + WebView) + 별도 Kotlin 배경/위젯 모듈로 확정. (APK 경량화·< 50MB 목표와 정합)

2.2 배경-앱 UX 브리지: 위젯 + 알림 (오버레이/더블탭 폐기)

SYSTEM_ALERT_WINDOW(다른 앱 위에 그리기) 심사 리스크 + 런처별 터치 가로채기 때문에 "배경 더블탭 → 플로팅 패널"은 폐기한다.

  • 대안 1 (P0) — 홈 위젯 스마트 버튼: RemoteViews에 [먹이주기]/[청소하기] 버튼. 탭 → PendingIntent → 백그라운드 서비스가 로컬 캐시 변경.
  • 대안 2 (P1) — 진행형 알림 액션: 상단 알림창에 'Aqua Desk 제어센터' 상주 노티 + 액션 버튼. (Android 13+ POST_NOTIFICATIONS 런타임 권한 필요)

2.3 ⚠️ 핵심 이음새: "비가시 상태 먹이" + 크로스 프로세스 IPC

가장 흔히 누락되어 **"먹였는데 배경은 그대로"**가 되는 지점. 반드시 설계에 못 박는다.

  1. 비가시 시 애니 큐잉: 위젯/알림으로 먹이를 줄 때 홈의 라이브 배경은 가려져 onVisibilityChanged(false)(= §2.4 표에서 0 FPS) 상태다. → 상태 변경은 캐시에 즉시 커밋하되, 연출은 큐에 적재 후 다음 onVisibilityChanged(true)(홈 복귀) 때 재생.
  2. IPC 명시: 위젯/알림 처리 컴포넌트가 WallpaperService.Engine에 "캐시 변경, 리로드"를 알리는 채널이 필요. → 설계 확정: 동일 프로세스(android:process 미지정) + ContentProvider 기반 ContentObserver(LocalBroadcast는 프로세스 경계·deprecated 문제로 폐기). 상세 설계서 03.

2.4 렌더러 확정 + 셰이더 게이팅 정책

  • OpenGL ES 2.0 파이프라인을 네이티브 배경 렌더러 기본 스펙으로 강제(Android 10 / API 29+). Canvas 2D로는 풀스크린 프래그먼트 셰이더(God Rays·굴절) 불가.
  • 터치 ripple은 3프레임 스프라이트 파티클로 구현(RenderEffect/AGSL는 API 31/33+라 최소 SDK에서 불가 → 회피).
  • 배터리/CPU < 5%·RAM < 30MB 목표를 위한 게이팅 정책:
기기 상태 셰이더 구동 FPS
런처 포그라운드 God Rays + 굴절 풀가동 30 (터치 시 일시 상향, 디스플레이 주사율 캡)
장시간 미터치 굴절 일시정지, God Rays 루프 연장 15
절전 모드 ON 모든 셰이더 OFF, 순수 도트만 15
화면 OFF / 타 앱 onVisibilityChanged(false) 즉시 감지 0 (렌더 정지)

2.5 터치/제스처의 런처 의존성

라이브 배경의 onTouchEvent/롱탭은 런처가 가로챌 수 있다(홈 롱프레스 = 위젯 추가 메뉴 등).

  • 이름표(2초 롱탭) 같은 정밀 제스처의 1차 UX는 앱 미러 뷰(확실)에 두고, 배경 롱탭은 best-effort 보너스로 취급.

2.6 iOS 대안 + App Store 4.2 리스크

  • iOS는 서드파티 라이브 배경 불가 → 위젯(iOS 16 정적 / 17+ 인터랙티브 버튼) + 앱 내 Mirror + (옵션)Live Activity로 체감 동등화.
  • ⚠️ App Store 4.2 (Minimum Functionality): 앱이 원격 웹뷰 래퍼로만 보이면 리젝 위험. → 위젯·Mirror·App Intent 등 네이티브 기능을 충분히 넣어 단순 래퍼가 아님을 입증. 오프라인 동작 고려(웹앱 다운 시 Mirror 빈 화면 방지).

3. 인게임 경제 및 BM

  • 생산비 폭발을 막는 구현 전략은 §5에 분리.

3.3 구독: 아쿠아 패스

§1.3에서 확정(편의·유대 판매, 죽음 방지 아님).

3.4 IAP 가격 사다리 (보정) — 진주 팩 + 스타터팩 + 상품

기준: 1 진주 ≈ 120원. 수치는 별첨 경제표에서 최종 튜닝.

(A) 진주 팩 — 보너스 체증형 (매출의 토대, 신규 추가)

가격(원) 진주 보너스
1,200 10 –
5,500 50 +9%
12,000 115 +15%
25,000 260 +30%
49,000 540 +35% (고래)

(B) 스타터팩 (첫구매 1회, 신규 추가): 2,900원 — 진주 30 + 한정 장식 + 코인 보너스.

(C) 상품 — 가격 레벨 교정

상품 제미나이 원안 교정안 비고
테마 스킨(핵심·반복) 진주 150 (18,000원) 진주 5080 (6,0009,600원) $13는 충동구매 대역($2.996.99) 대비 23배 → 전환율 저하
한정/번들 테마 – 진주 120~150 18,000원+는 한정/번들에 배치
신화 히어로 어종(확정 분양) 진주 400 (48,000원) 유지 고래 앵커. 가챠 아닌 확정 판매 = Route A 정합

3.5 리워드 광고 연계

캐주얼 매출의 큰 축. 낚시 스태미나 +1, 오프라인 보상 2배, 상점 무료 리프레시 등에 리워드 비디오 연결.

3.6 화폐 개수 관리 (하트 처리)

코인·진주·스태미나 + 하트 = 4종은 라이트 캐주얼에 인지부하가 크다. → 권장: 하트를 정식 화폐가 아닌 소셜 카운터로 두고 일정량 모이면 코인으로 자동 환산. (별도 상점/환율 신설 회피)

4. 핵심 메타 시스템

4.1 수집 메타 (진행의 척추)

  • 3티어 희귀도: Common → Rare → Cosmic/Mythic.
  • 멀티 어항 락인: 1번 어항 도감 80% 달성 시 코인 소모로 2번 어항 해금 → 종단 콘텐츠.
  • 도감 마일스톤 버프: 세트 완성 시 초당 코인 +5% 등 패시브.
    • ⚠️ 인플레 주의: 버프 누적이 코인 가치를 희석하므로, 싱크(어항2·3·장식 가격)를 비례 상향해 균형.

4.2 꾸미기·미학 시스템

  • 단순 슬롯 배치를 넘어 물-색감/조명/무드/테마가 어항 전체를 바꿈.
  • 어항 평점(풍수/감성 점수) 도입 → 예쁘게 꾸미면 보상(코인 보너스/도감 점수). 미학을 진행으로 전환.
  • 물고기-식물 시너지로 수집과 꾸미기를 연결.

4.3 소셜 / 바이럴 루프 (+ 보안)

  • 딥링크 공유: 어항 스냅샷 카드 + 딥링크를 SNS로 내보내기.
    • ⚠️ 보안 교정: 링크에 raw user_id 노출 금지(RLS 주체 키). → 불투명 share token(매핑 테이블) 발급.
  • 방문 + 버블탭: 친구 어항을 웹 뷰어로 미러링 → 화면 탭으로 하트 기포 선물. 친구가 다음 배경 sync/visibility 때 하트 파문 + 선물박스 수령.
    • 📌 "다음 홈 켤 때 즉시"가 아니라 다음 동기화 시점임을 명확히(즉시성 원하면 FCM 푸시로 sync nudge).
    • 어뷰징 방지: 하트 선물 레이트 리밋 / 친구 한정 고려.

4.4 시스템적 감정 소유 (이름 · 성격)

  • 이름 짓기: 개체 인스턴스에 닉네임. 배경 2초 롱탭 시 이름표 팝업(단, §2.5 — 1차는 미러 뷰).
  • 고유 성격(Nature Traits) = FSM 발동 가중치:
    • 겁쟁이: Scatter 범위 2배
    • 먹보: 먹이 이동속도 1.5배
    • 호기심: Peek 확률 +30%
    • 외톨이: 군집 이탈, 외곽 단독 패트롤

4.5 낮/밤 환경 사이클 (전 테마 코어)

특정 테마 전유물이 아닌 전 테마 기본 시스템으로 격상.

  • 기기 로컬 시간 기준 06:00–18:00 주간 / 18:00–06:00 야간.
  • 야간: GL 렌더러가 다크 인디고 오버레이 + 물고기 눈/야광 오브젝트만 Additive 블렌딩으로 점등.
  • 📌 하드컷 대신 30~60분 dusk/dawn 보간 + 설정에서 고정(항상 주간/야간) 오버라이드 제공.

5. 콘텐츠 생산성 전략 (아트 방폭)

테마 × 어종 × 모션의 곱셈 폭발을 막기 위한 전략. (BM 전제 조건)

5.1 ⚠️ 3단 분리 — 팔레트 스왑만으로는 부족

계층 기법 비용 적용
① 컬러 스왑 LUT/색상 시프트 셰이더 거의 0 모든 어종의 테마별 색 변조
② 테마 FX 패스 Additive glow/bloom 셰이더 저렴(GL) 발광·홀로그램 등 형태가 아닌 빛 효과 (제미나이 안에서 누락됐던 계층)
③ 전용 도트 신규 스프라이트 비쌈 히어로 어종 1~2종 한정

"사이버네틱 스킨/홀로그램 산호"는 ①(색)이 아니라 ②(빛)다. ②를 명시하지 않으면 ③(고비용 아트)로 흘러간다.

5.2 스켈레톤 템플릿 — 줄여주는 것은 "로직"이지 "드로잉"이 아님

  • 어종을 3형(방추형·원반형·장형) 으로 규격화, 동일형은 Idle/Scatter/Peek/Yawning의 프레임 진행·트랜스폼 로직 100% 공유.
  • ⚠️ 현실: 픽셀 프레임은 결국 어종마다 그려야 한다("정점 치환"식 메시 디폼은 01/02의 "순수 프레임·보간 없음"과 충돌). → 템플릿의 이득은 일관성 + 엔지니어링 시간이고, 드로잉 공수는 거의 안 줄어든다. 아티스트 캐파 산정에 반영.

5.3 히어로 어종 집중

테마 시그니처가 되는 최고 희귀도 히어로 어종 1~2종에만 전용 도트(③)를 집중. 나머지 롱테일은 ①+②로 처리.

6. 낚시 미니게임

6.1 4단계 플로우

[캐스팅] → [입질 대기] → [릴링(줄다리기)] → [결과/보상]
 게이지 타이밍   "!" 1.0s 내 탭   그린존 유지(탭&홀드)   서버 검증
  • 캐스팅: 힘 게이지, Perfect 존 적중 시 희귀종 확률 +10%
  • 입질: 찌 가라앉음 + "!" → 1.0초 내(기존 0.5초에서 완화, 캐주얼·중장년 배려) 탭
  • 릴링: 무작위 이동 그린존에 찌를 3초 유지(탭/홀드 ↑, 떼면 ↓). 상·하단 끝 = 실패

6.2 스킬 → 보상 반영

보상이 100% 서버 RNG면 조작이 무의미. → 2축 스킬 매핑:

  • 캐스팅 Perfect → 어종 희귀도 확률
  • 릴링 Time-in-Zone ≥ 90% → 'Perfect Catch', 해당 어종 크기/무게 상위 10% 최대어 확정

6.3 ⚠️ Optimistic UI + 서버 정합 규칙

  • 릴링 성공 즉시 선제 성공 연출(물고기 들어올리기 1.5~2초) 구동, 그동안 fishing-resolve Edge Function 통신.
  • 불변 규칙: 서버는 "무엇을 잡았나"만 결정하고 "잡았나/못 잡았나"는 절대 뒤집지 않는다. (성공 연출 후 "사실 실패" 금지)
  • 실패 폴백: Edge Function 호출 실패 시 로컬 임시 지급 → 재동기화 큐잉. 통신 단절로 잡은 물고기가 증발하지 않도록.
