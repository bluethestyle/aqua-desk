## 2. 컴포넌트 책임

| 컴포넌트 | 책임 | 비책임(하지 않는 것) |
|----------|------|----------------------|
| **Wallpaper Engine** | 스냅샷 렌더, FSM 애니, 셰이더, 터치 파티클 | 네트워크·게임 로직·결제 |
| **Widget/Notification** | 퀵 먹이/청소 트리거(→ QuickActionService) | 렌더(스냅샷 이미지 표시만) |
| **QuickActionService** | 위젯/알림 액션 처리 → **서버 RPC(`feed_fish`/`clean_aquarium`) 호출** + 로컬캐시 optimistic + IPC 통지 | 경제 직접 쓰기(서버 권위) |
| **WallpaperBus** | 크로스 컴포넌트 IPC = **ContentObserver 래퍼**(ContentProvider 기반) | — |
| **Local Cache** | 배경용 경량 스냅샷 + 스프라이트 번들 | 진실의 원천 아님(읽기 캐시) |
| **Shell + WebView** | 웹앱 호스팅, JS 브리지, 딥링크 | UI 자체(웹이 담당) |
| **Web App** | 모든 인터랙티브 UI, Supabase 호출/RPC | 배경 렌더·서버 권위 쓰기 |
| **packages/game-spec (TS)** | 경제 계산·FSM 규칙(클라/네이티브/문서 공유 스펙, I/O 없음) | I/O |
| **Supabase** | **진실의 원천**, 권한(RLS), 서버 권위 보상/경제 RPC | 클라 렌더 |

> **IPC 단일화([03](./03-네이티브-안드로이드-설계.md))**: `WallpaperService`/`QuickActionService`/`AquariumWidgetProvider`는 **동일 프로세스**(`android:process` 미지정)에서 구동한다. 캐시 변경 신호는 LocalBroadcast를 폐기하고 **ContentProvider 기반 `ContentObserver`**로 전달한다(프로세스가 분리돼도 안전). `WallpaperBus`는 이 ContentObserver 래퍼다. 컴포넌트명은 **`QuickActionService`로 통일**한다(이전 `BackgroundService` 별칭 제거).

## 3. 진실의 원천(Source of Truth) & 동기화 모델

- **SoT**: Supabase `aquariums`(+ 연관 테이블). 모든 상태 변경은 서버 RPC 내부에서 `version` 증가.
- **로컬 캐시**: 배경 렌더 전용 **읽기 캐시**(스냅샷). 권위 없음.
- **동기화 시점**:
  1. 웹앱 포그라운드 진입/저장 시 → 즉시 DB upsert(서버 RPC 또는 owner-write 컬럼) + `version++`
  2. 네이티브 앱 resume 시 → 브리지로 즉시 스냅샷 전달
  3. 백그라운드 → `SyncWorker`(WorkManager, 15~30분, OS 정책 내)
  4. 수동 새로고침

### 3.1 충돌/정합 규칙 — version CAS (lost-update 방지)

- 프로토타입은 단일 기기 가정이지만, **last-write-wins를 폐기**하고 **version CAS(Compare-And-Swap)**로 lost-update를 방지한다.
- 모든 상태변경 RPC는 다음 패턴으로 갱신한다:
  ```sql
  update aquariums set ... , version = version + 1
   where id = :id and version = :expected_version;
  -- 영향 0행 = version 불일치 → 'conflict' 반환
  ```
- `version` 불일치(`conflict`) 반환 시 **클라는 서버에서 최신 스냅샷을 refresh**한 뒤 재시도한다(서버 우선 + 클라 강제 리프레시, UX 고지).
- 멀티 기기 병합은 추후([기획서 04 §8.3](../기획서/04-서비스-고도화-및-리스크-대응.md#83-미해결--추후)).

### 3.2 익명 → 이메일 계정 승격(병합)

- 비로그인 진입은 Supabase **익명 인증**으로 시작하고, `auth.users` 행 생성 시 부트스트랩 트리거(`handle_new_user`, [02 §3](./02-데이터-모델.md))가 `profiles`/`wallets`를 생성한다.
- 이후 이메일로 영구 전환할 때 **새 계정을 만들지 않고** Supabase `linkIdentity`(계정 승격)로 **동일 `user_id`에 이메일 신원을 연결**한다 → 익명 단계에서 쌓인 어항/도감/지갑 데이터가 그대로 보존된다.
- `user_id`가 유지되므로 RLS 정책(`auth.uid() = user_id`)과 모든 권위 테이블 소유권이 자동으로 일관된다(별도 데이터 이전 작업 불필요).

## 4. 주요 데이터 흐름

> 아래 모든 경제·수집·보상 갱신은 **클라가 테이블을 직접 쓰지 않고 서버 RPC를 경유**한다. 클라의 로컬 캐시 변경은 어디까지나 **optimistic 표시용**이며, 권위는 서버 RPC 결과다.

### 4.1 꾸미기 저장 → 배경 반영

```
Web Decorate 저장
  → aquariums.slots UPDATE (owner write; theme_id 변경은 set_aquarium_theme RPC)
  → version++ (서버에서 증가; water_quality/version/rating은 서버 권위)
  → (앱 포그라운드면) Bridge.applySnapshot(newSnapshot)
  → (백그라운드면) SyncWorker가 다음 주기에 pull
  → Local Cache 갱신 → ContentObserver 통지 → Wallpaper Engine reload
```

### 4.2 위젯/알림 먹이 (★핵심 이음새 R1 — 서버 권위 경유)

```
Widget [먹이] 탭
  → PendingIntent → QuickActionService
  → 저장 토큰으로 feed_fish(aquarium_id) RPC 호출  [서버 권위: hunger 갱신 + version CAS]
       · 토큰 없음/만료 → 위젯 버튼 비활성 + "앱 열기" 유도(서버 쓰기 시도 안 함)
  → 성공 시 Local Cache optimistic 변경(hunger↓) + pendingAnims.push('feed-drop')
       · version conflict → 서버 최신 스냅샷 refresh 후 캐시 재구성
  → ContentObserver 통지 → Wallpaper Engine:
       · 가시 상태면 즉시 드롭 애니 재생
       · 비가시면 AnimQueue에 적재 → onVisibilityChanged(true) 때 flush
```

> 청소도 동일하게 `clean_aquarium(aquarium_id)` RPC를 경유한다(`water_quality`/`version` 서버 권위). 위젯·알림·앱 모두 같은 RPC를 호출한다(중복 구현 없음).

### 4.3 낚시 (서버 권위 + Optimistic, 멱등키 = fishing_sessions.id)

```
Web 낚시 진입
  → start_fishing(spot_id) RPC  [lazy 스태미나 재생 → stamina-1 → fishing_sessions insert]
       · 스태미나 부족 → 거부(연출 진입 차단)
       · 성공 → session_id 반환  (★이후 모든 보상 멱등키 = fishing_sessions.id)
  Web 릴링 성공
  → 선제 성공 연출(1.5~2s) 즉시 구동 [Optimistic]
  → fishing-resolve(session_id, skill) Edge Fn(service role) 호출
       · session 미consumed 검증 → spot species_pool+rarity_weights+seed로 종 결정
       · skill로 size_pct·희귀확률 보정 → fish_instances insert + dex upsert
       · session.consumed = true + reward_fish_instance_id 연결
       · (이미 consumed면 기존 reward 반환 = 멱등)
  → 연출 종료 시 결과 팝업 연결
  → 통신 지연/실패 시:
       · 연출 종료 후에도 응답 미도착 → 스피너
       · 타임아웃 → fishing_sessions.id 기준 재동기화(멱등 재호출로 동일 보상 회수)
```

> **불변 규칙**: 서버는 "무엇을 잡았나"만 결정하고 "잡았나/못 잡았나"는 뒤집지 않는다. **보상 쓰기는 전부 서버**(`fish_instances`/`dex_entries`)이며, 클라의 임시 표시는 `fishing_sessions.id` 멱등키로 항상 서버 결과로 수렴한다('연출 종료 == 응답 도착' 가정은 폐기).

### 4.4 소셜 하트 선물 (토큰 보유자 한정 + 서버 권위)

```
Web 어항 Viewer(get_shared_aquarium(token)으로 진입, user_id 미노출)에서 버블탭
  → send_heart(to_token) RPC
       · 토큰 → 대상 user 해석, 자기선물 차단
       · 레이트리밋(대상별 일 5회) → gifts insert (서버 권위)
  → 대상의 다음 sync(SyncWorker/resume) 때 claim_gifts() 호출
       · 미수령 gifts → wallets.hearts 적립 + claimed=true
       · hearts 임계(100) 도달 시 claim 내에서 coins로 자동 환산(100 hearts → 1000 coins)
  → 하트 파문 연출(visibility 시) + 선물박스 수령
```

> 프로토타입은 `friends` 테이블이 없다. 소셜은 **토큰 기반**으로, **내 `share_token`을 받은 누구나** 하트를 보낼 수 있다(레이트리밋 + 자기선물 차단). '친구 한정'이 아니라 **'토큰 보유자 한정'**이다([02](./02-데이터-모델.md), [기획서 04 §4.3](../기획서/04-서비스-고도화-및-리스크-대응.md#43-소셜--바이럴-루프--보안)). RPC명은 스네이크케이스 `send_heart`로 통일한다.

## 5. 인증 모델 (★핵심 이음새 R8 — 단일 refresh 주체)

- **웹앱**: Supabase Auth(익명/이메일) — `anon key` + RLS. 익명→이메일은 `linkIdentity`로 승격([§3.2](#32-익명--이메일-계정-승격병합)).
- **네이티브 백그라운드 동기화**: 앱을 열지 않고 `SyncWorker`가 DB를 읽으려면 **세션이 필요**하다.
  - 사용자가 앱(WebView)에서 로그인 → 브리지 `AquaDesk.setAuthSession(refreshToken)`로 네이티브에 전달.
  - 네이티브는 **Android Keystore 기반 암호화 저장소**(EncryptedSharedPreferences는 deprecated이므로 미사용 / iOS Keychain)에 refresh token 저장.
  - `SyncWorker`는 저장된 토큰으로 access token 갱신 후 스냅샷 pull.
- **R8 — 단일 refresh 주체 + 회전 폴백**:
  - **네이티브를 토큰 refresh의 단일 주체**로 둔다. 웹앱은 resume 시 브리지 `getAuthSession()`으로 **네이티브 세션을 읽어 재사용**하고, **웹 독립 refresh는 금지**한다(refresh-token rotation 환경에서 양쪽이 동시에 갱신하면 토큰이 무효화되는 문제 방지).
  - **invalid refresh(회전 실패/만료) 시 폴백**: 토큰 파기 → 위젯 퀵액션 버튼 비활성 + 배경은 마지막 캐시로 정적 표시 → 앱에서 **재인증 유도**.

## 6. 브리지 계약 (실패/에러 콜백 + 버전 협상)

- 각 브리지/딥링크 호출은 **성공뿐 아니라 실패·에러 콜백**을 명시한다(예: `feed_fish` RPC 실패, 토큰 만료, version conflict는 네이티브→웹 또는 콜백으로 사유 전달).
- **버전 협상**: 브리지는 `minBridgeVersion`을 노출하고, 웹앱/네이티브가 서로 호환 가능한 최소 버전을 확인한다. 미충족 시 해당 기능을 graceful degrade(앱 업데이트 유도)한다.
- 계약 본문(`AquaDeskBridge` 타입, `getAuthSession`/`setAuthSession`, 딥링크 스킴, 에러 콜백 시그니처)은 [02 §5](./02-데이터-모델.md#5-브리지--딥링크-api)에서 단일 정의한다.
