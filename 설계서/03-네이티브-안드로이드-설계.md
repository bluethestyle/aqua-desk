# 03. 네이티브 설계 — Android (P0)

> v2 (서버권위·RLS 재작성 반영)

> iOS(위젯+Mirror)는 프로토타입 후순위(P1). 본 문서는 핵심 차별점인 Android 배경에 집중.
> **최소 SDK 기준: API 29(Android 10), OpenGL ES 2.0.** `RenderEffect`/AGSL는 API 31/33+라 최소 SDK에서 불가 → 회피(스프라이트 파티클 + GL 셰이더로 대체).

## 0. v2 핵심 변경 요약 (서버 권위·IPC 단일화)

- **서버 권위**: 경제·수집·결제 상태는 클라가 직접 쓰지 않는다. feed/clean을 포함한 모든 상태 변경은 **서버 RPC**(`feed_fish`/`clean_aquarium` 등)로만. 로컬 캐시는 **optimistic 반영 + 재동기화**용 읽기 캐시이며 권위가 없다.
- **IPC 단일화**: `WallpaperService`/`QuickActionService`/`WidgetProvider`를 **동일 프로세스**(`android:process` 미지정)로 두고, 캐시 변경 신호는 **ContentProvider 기반 `ContentObserver`**로 전달한다. **LocalBroadcast는 제거.** `WallpaperBus` = `ContentObserver` 래퍼.
- **R8 단일 갱신 주체**: refresh 토큰 갱신은 **네이티브가 단일 주체**. 웹앱은 resume 시 `getAuthSession()`으로 네이티브 세션을 읽어 재사용(웹 독립 refresh 금지). invalid refresh → 재인증 유도 폴백.
- **토큰 저장**: `EncryptedSharedPreferences`(deprecated) 대신 **Android Keystore 기반 암호화 저장**.
- **위젯 webp**: 웹앱이 저장 시 `Canvas`로 스냅샷 webp를 생성·업로드. **Edge/native 합성은 폐기**(`snapshot-export`는 메타만 또는 제거).
- **셰이더**: 컬러 LUT(①) 외 **Theme FX 패스(② additive glow/bloom)**를 별도 패스로 추가. **dusk/dawn 30~60분 보간(lerp)** 렌더, 시계 = device local time, 설정 오버라이드.

## 2. 배경 렌더 파이프라인 (OpenGL ES 2.0)

```
GLRenderer.onDrawFrame():
  1. 가시성/게이트 체크 → FPS 결정 (30/15/0)
  2. 레이어 합성 (back→front):
       [배경 far/mid/near 패럴랙스] → [장식 슬롯] → [물고기 스프라이트] → [기포 파티클] → [터치 ripple 파티클]
  3. 포스트 처리 패스(게이트 ON일 때만):
       · ① 컬러 LUT 패스       — 테마별 색 변조(팔레트 스왑, sprites/theme/{theme}/lut.png)
       · ② Theme FX 패스       — Additive glow/bloom(발광·홀로그램 등 '빛' 효과). LUT와 분리된 별도 패스
       · Water Distortion       — 풀스크린 프래그먼트 셰이더, 저주기 sine UV offset
       · God Rays               — 대각 반투명 빛, sine 밝기
       · Day/Night              — dusk/dawn 30~60분 lerp 보간(아래 §2.1)
  4. swap
```

- 렌더 좌표는 스냅샷의 정규화(0..1) 좌표 → 화면 해상도 매핑(기기 다양성 흡수).
- 스프라이트 애니: **논리 12fps 프레임** 진행, 렌더는 게이트 FPS(보간 없음).
- **셰이더 3단 분리 정합**([기획서 04 §5.1](../기획서/04-서비스-고도화-및-리스크-대응.md#51--3단-분리--팔레트-스왑만으로는-부족)): ① 컬러 LUT = 거의 0 비용 / ② Theme FX(additive glow/bloom) = GL 저렴 / ③ 전용 도트 = 히어로 어종 한정(렌더가 아닌 에셋). ②를 **별도 패스로 명시**해야 ③(고비용 아트)로 흘러가지 않는다.

### 2.1 Day/Night dusk·dawn 보간 (전 테마 코어)

```
시계 = device local time (기획서 04 §4.5)
주간 06:00–18:00 / 야간 18:00–06:00
경계(06:00, 18:00) 전후 30~60분: dusk/dawn 가중치 t = clamp(경계까지 거리, 0..1)
  · 인디고 오버레이 알파 = lerp(day=0, night=0.45, t)
  · Additive 점등(물고기 눈/야광 오브젝트) 강도 = lerp(day=0, night=1, t)
설정 오버라이드: profiles.settings.dayNight = 'auto' | 'day' | 'night'
  · 'auto' → 위 시계 기준 / 'day'·'night' → 고정(보간 무시)
```

- **하드컷 금지**: 경계에서 즉시 전환하지 않고 30~60분 lerp로 dusk(황혼)/dawn(여명)을 표현.
- 스냅샷의 `dayNight`('auto'|'day'|'night')를 그대로 따르며, 'auto'일 때만 device local time으로 보간 계산.

## 3. FSM + 성격 가중치

```
Idle/Swim ──(배경 탭)──▶ Scatter ──(2s)──▶ Idle
          ──(연타)────▶ Peek    ──(끝)──▶ Idle
          ──(장시간)──▶ Yawn    ──(끝)──▶ Idle
          ──(불만족: satisfied=false)──▶ Sulk(반투명·은신, 생산중단)
                                          └─(먹이/청소로 satisfied=true)──▶ Idle
```

| 성격 | 가중치 |
|------|--------|
| timid | Scatter 트리거 반경 ×2 |
| gluttonous | 먹이 이동속도 ×1.5 |
| curious | Peek 확률 +30% |
| lone | 군집 알고리즘 이탈, 외곽 패트롤 |

- **스프라이트 state enum**: `idle | swim | scatter | peek | yawn | sulk` (Sulk 추가, [02 §6](./02-데이터-모델.md#6-스냅샷-계약-native--web-공유-json) 정합).
- **위치 권위는 네이티브 FSM**: 스냅샷의 `x/y`는 **'초기 배치 힌트'(서버 시드)**일 뿐, 런타임 물고기 위치 권위는 이 `FishFSM`이다. 매 동기화마다 위치를 강제 리셋하지 않는다.
- **불만족(Sulk)**: `satisfied=false`(스냅샷 파생) 시 진입. 별도 컬럼 없이 hunger/water_quality에서 서버가 파생. 회복은 `feed_fish`/`clean_aquarium` RPC 성공 → 다음 스냅샷에서 `satisfied=true`.

## 4. ★핵심 이음새 — 비가시 큐잉 + IPC (단일화)

### 4.1 가시성 제어 + GL 생명주기

```kotlin
override fun onVisibilityChanged(visible: Boolean) {
  if (visible) {
    renderer.resumeGLThread()   // 렌더 스레드/GL 컨텍스트 resume
    animQueue.flush()           // 큐 적재분 재생
  } else {
    renderer.pauseGLThread()    // 렌더 정지(0fps) — 배터리
  }
}

// Surface 생명주기 ↔ GL 리소스
override fun onSurfaceCreated(...) {
  // GL 리소스 재생성: 셰이더 프로그램 컴파일·링크, VBO, 텍스처(아틀라스/LUT) 업로드
}
override fun onSurfaceDestroyed(holder) {
  renderer.releaseGLResources()  // 텍스처/VBO/프로그램 delete, EGL 컨텍스트 정리
}
```

- **GL 컨텍스트/렌더 스레드 pause/resume**: 비가시 → 렌더 스레드 정지(0 FPS), 가시 → resume.
- **Surface 생성·파괴 시 GL 리소스 정리·재생성**: Surface 재생성(화면 회전·테마 변경·메모리 회수 후 복귀)에서 컨텍스트가 무효화될 수 있으므로, `onSurfaceCreated`에서 셰이더/텍스처/VBO를 **재업로드**, `onSurfaceDestroyed`에서 **해제**한다. 컨텍스트 손실 후 stale 핸들 사용 시 검은 화면/크래시 방지.

### 4.2 위젯/알림 → 서버 RPC → 배경 통지 흐름 (서버 권위)

```
[Widget 버튼] --PendingIntent--> QuickActionService (동일 프로세스)
   0) AuthStore 토큰 확인
        · 비로그인/토큰 만료 → §4.4(위젯 비활성 + 앱 열기 유도)로 분기, 이하 중단
   1) 서버 RPC 호출(저장 토큰):  feed_fish(aquarium_id)  또는  clean_aquarium(aquarium_id)
        · 서버가 hunger/water_quality 갱신 + version CAS (서버 권위)
   2) LocalCacheStore: optimistic 반영(hunger↓ / waterQuality=1.0 + pendingAnims.push(...))
        · RPC 성공 응답의 version으로 캐시 동기화
        · conflict(version 불일치) 응답 → 캐시 refresh(서버 스냅샷 재pull)
   3) WallpaperBus.notify()  →  CacheSignalProvider URI에 notifyChange()
          │  (ContentObserver 트리거, LocalBroadcast 아님)
          ▼
AquariumWallpaperService 의 ContentObserver.onChange:
   · LocalCacheStore reload
   · visible?   → animQueue.play(now)
     invisible? → animQueue.enqueue()  → 다음 onVisibilityChanged(true)에 flush
```

> 이 큐잉이 없으면 "알림창에서 먹였는데(배경 가려짐) 홈 복귀 시 아무 일도 없던" 버그 발생(R1, [기획서 04 §2.3](../기획서/04-서비스-고도화-및-리스크-대응.md#23--핵심-이음새-비가시-상태-먹이--크로스-프로세스-ipc)).

### 4.3 IPC = ContentProvider 기반 ContentObserver (LocalBroadcast 제거)

```kotlin
// CacheSignalProvider — 통지 전용 ContentProvider
//   authority: "com.aquadesk.cache"
//   URI: content://com.aquadesk.cache/snapshot
class CacheSignalProvider : ContentProvider() { /* query 등은 no-op 또는 메타 */ }

// WallpaperBus = ContentObserver 래퍼
object WallpaperBus {
  val SIGNAL_URI: Uri = Uri.parse("content://com.aquadesk.cache/snapshot")
  fun notify(ctx: Context) =
    ctx.contentResolver.notifyChange(SIGNAL_URI, /*observer*/ null)
  fun observe(ctx: Context, cb: () -> Unit): ContentObserver {
    val obs = object : ContentObserver(Handler(Looper.getMainLooper())) {
      override fun onChange(self: Boolean) = cb()
    }
    ctx.contentResolver.registerContentObserver(SIGNAL_URI, false, obs)
    return obs
  }
}
```

- **왜 ContentObserver인가**: 동일 프로세스 기본이지만, 제조사 절전/메모리 정책으로 위젯/서비스가 **프로세스 분리되어 기동돼도 `ContentObserver`는 IPC로 안전하게 통지**된다. LocalBroadcast는 동일 프로세스 한정이라 이 시나리오에서 누락 위험이 있어 **제거**한다.
- 등록 해제: `Engine.onDestroy`에서 `unregisterContentObserver`.

### 4.4 위젯 비로그인 / 토큰 만료 동작

- `QuickActionService`는 액션 처리 전 `AuthStore`에서 토큰 유효성을 확인한다.
- **비로그인 또는 refresh 토큰 만료/무효**:
  - 위젯 `[먹이][청소]` 버튼을 **비활성(disabled) 표시**(흐림 + "앱에서 로그인" 라벨).
  - 버튼 탭 시 RPC 대신 **앱 열기 인텐트**(WebAppActivity, 로그인 화면 딥링크 `aquadesk://login`) 발사 → **앱 열기 유도**.
  - optimistic 캐시 변경도 하지 않는다(서버 권위 위반 방지).
- 위젯 갱신 주기/`AppWidgetProvider.onUpdate`에서 토큰 상태를 반영해 버튼 enabled/disabled를 RemoteViews에 세팅.

## 5. 터치 / 파티클

- `Engine.setTouchEventsEnabled(true)` + `onTouchEvent`로 tap 좌표 취득.
- **ripple**: `RenderEffect`/AGSL 미사용(API 31/33+ → 최소 SDK API 29 미만 회피) → **3프레임 스프라이트 파티클**을 탭 좌표에 스폰.
- 인근 물고기 → `FishFSM`에 Scatter 트리거(성격 반경 적용).
- ⚠️ **런처 의존 caveat**: 런처가 터치/롱프레스를 가로챌 수 있음(홈 롱프레스 = 위젯 추가 메뉴 등). → **정밀 제스처(이름표 롱탭)의 1차 UX는 앱 미러 뷰**(확실), 배경 롱탭은 best-effort 보너스([기획서 04 §2.5](../기획서/04-서비스-고도화-및-리스크-대응.md#25-터치제스처의-런처-의존성)).

## 6. 백그라운드 동기화 + 인증 (R8 — 네이티브 단일 갱신 주체)

```
앱 로그인(WebView) → BridgeModule.setAuthSession(refreshToken)
   → AuthStore(Android Keystore 암호화) 저장

SyncWorker(WorkManager, 15~30분 + resume 즉시):
   1) AuthStore에서 refresh → access 갱신   ★네이티브가 단일 refresh 주체
   2) GET aquarium snapshot (변경분/version)
   3) LocalCacheStore 갱신 + 스프라이트 번들 필요 시 다운로드
   4) WallpaperBus.notify (ContentObserver)
   refresh 무효(invalid) → 토큰 파기 + 재인증 유도 폴백(아래)
```

### 6.1 R8 단일 갱신 주체 + 웹앱 세션 재사용

- **네이티브가 refresh의 단일 주체**: refresh→access 갱신은 `SyncWorker`(네이티브)만 수행한다. 웹앱은 **독립 refresh 금지**.
- **웹앱 resume 시**: WebView 웹앱은 resume 시 `getAuthSession()` 브리지로 **네이티브가 보유한 현재 세션(access/refresh)을 읽어 재사용**한다. 토큰 회전(rotation)으로 인한 refresh 토큰 경쟁(두 곳에서 동시 refresh → 한쪽 무효화)을 방지.
- **재인증 폴백**: refresh가 invalid(만료·회전 실패·로그아웃)면 → 토큰 파기 + 배경은 마지막 캐시로 정적 표시 + 앱/웹에 **재인증 유도**(로그인 화면). 위젯 버튼은 §4.4대로 비활성.

```typescript
// Bridge 추가(02 §5 정합): Web ← Native 세션 읽기
//   getAuthSession(): Promise<{ accessToken: string; refreshToken: string } | null>
//   → 웹앱은 이 세션으로 Supabase 클라이언트 초기화(자체 refresh 비활성)
```

- WorkManager 제약(제조사 절전) 대비: 사용자에게 "배터리 예외" 안내(P1).

## 7. 위젯 / 알림 설계

| 구성 | 사양 |
|------|------|
| Widget(중/대형) | `snapshots/{userId}/{idx}.webp` 표시 + `[먹이][청소]` 버튼(RemoteViews). 비로그인 시 버튼 비활성(§4.4) |
| Ongoing Notification(P1) | 'Aqua Desk 제어센터' + 액션 버튼. Android 13+ `POST_NOTIFICATIONS` 런타임 권한 |
| 갱신 | 위젯은 throttle 됨 → 실시간 애니 ✗, **스냅샷 교체 + 버튼 트리거(서버 RPC)**만 |

### 7.1 위젯 webp = 웹 생성 (Edge/native 합성 폐기)

- **스냅샷 이미지 생성 주체 = 웹앱**: 웹앱이 어항 저장 시 `Canvas`(또는 OffscreenCanvas)로 현재 어항을 렌더 → **webp로 인코딩 → Storage `snapshots/{userId}/{idx}.webp` 업로드**.
- **Edge Function/네이티브 합성은 폐기**: `snapshot-export` Edge Function은 **메타만 반환(또는 제거)**한다([04 §5](./04-웹앱-백엔드-설계.md#5-서버-권위-함수rpc-단일-진실원), [01 §1](./01-시스템-아키텍처.md)). 위젯/배경은 이 webp를 표시만 한다(합성 책임 없음).
- 위젯/공유 미리보기는 동일한 `snapshots/{userId}/{idx}.webp` 자원을 공유.

> 위젯은 **위치 기반 파문 불가**(RemoteViews 한계). 자유 터치 연출은 배경/미러 전용.

## 8. WebView 컨테이너 + 브리지

- `WebAppActivity`: Fullscreen `WebView`, UA에 `AquaDesk-Android` 부여(웹이 safe-area/네이티브 모드 감지).
- `BridgeModule`(`@JavascriptInterface`): [02 §5](./02-데이터-모델.md#5-브리지--딥링크-api) 계약 구현.
  - 추가 메서드 **`getAuthSession()`**: 웹앱 resume 시 네이티브 세션 재사용(R8, §6.1).
  - 각 브리지/딥링크 호출은 **실패·에러 콜백 + 버전 협상(minBridgeVersion)** 을 포함(02 §5 v2 정합).
- 딥링크 인텐트 필터: `aquadesk://` → 라우팅(`sync-complete` / `aquarium/{token}` / `login`).

## 9. 온보딩 (라이브 배경 설정 + 첫 물고기 매직 모먼트)

> "첫 60초 매직 모먼트"([기획서 04 §8.3](../기획서/04-서비스-고도화-및-리스크-대응.md#83-미해결--추후))의 네이티브 흐름. 라이브 배경 설정 마찰을 최소화한다.

### 9.1 라이브 배경 설정 흐름 (ACTION_CHANGE_LIVE_WALLPAPER)

```kotlin
// 온보딩 CTA "내 어항을 배경으로" → 라이브 배경 미리보기/설정 화면으로 직행
val intent = Intent(WallpaperManager.ACTION_CHANGE_LIVE_WALLPAPER).apply {
  putExtra(
    WallpaperManager.EXTRA_LIVE_WALLPAPER_COMPONENT,
    ComponentName(context, AquariumWallpaperService::class.java)   // 우리 서비스 선지정
  )
}
startActivity(intent)
// 폴백(제조사 미지원): ACTION_LIVE_WALLPAPER_CHOOSER → 목록에서 선택 안내
```

- `EXTRA_LIVE_WALLPAPER_COMPONENT`로 **우리 서비스를 선지정**해 사용자가 목록에서 찾는 마찰을 제거(미지원 기기는 chooser 폴백).
- 설정 미완료 시에도 앱 미러 뷰로 어항을 즉시 보여줘 가치 선전달.

### 9.2 첫 물고기 매직 모먼트

```
1) 가입/익명 진입 → 부트스트랩(서버 trigger로 profile/wallet 생성)
2) 튜토리얼 낚시 1회(start_fishing → fishing-resolve, 서버 권위) → 첫 물고기 확정 분양
3) "배경으로 만나기" CTA → §9.1 라이브 배경 설정
4) 홈 복귀 → onVisibilityChanged(true) → animQueue.flush로 첫 물고기 등장 연출(peek)
```

- 첫 물고기는 서버가 결정·지급(보상 쓰기는 서버). 클라는 연출만.

## 10. 동시성 / 정합 (version CAS)

- 모든 상태변경 RPC(`feed_fish`/`clean_aquarium`/`collect_offline` 등)는 **version CAS**(`UPDATE ... WHERE id=? AND version=?`)로 lost-update를 방지. 불일치 = `conflict` 반환.
- 네이티브 측 `conflict` 처리: optimistic 캐시 롤백 → 서버 스냅샷 **강제 refresh**(SyncWorker pull) → `WallpaperBus.notify`. last-write-wins를 CAS로 대체([01 §3.1](./01-시스템-아키텍처.md#31-충돌정합-규칙)).
